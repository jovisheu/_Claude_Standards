# 登入、密碼與忘記密碼實作規範

自 `CLAUDE.md`「資安防禦規範」移出的實作細節，不會自動載入。以下時機須先讀本檔：

* `new-project` 建立登入、密碼、忘記密碼、前端登入狀態等功能時。
* `owasp-check` 檢查「身分驗證失效」類別時。
* 在既有專案修改上述功能時。

## 錯誤次數鎖定

* 帳號或密碼錯誤即記錄（帳號不存在也記錄），以最近 N 分鐘內的錯誤次數判斷是否鎖定（次數與分鐘數放設定檔）。
* 鎖定期間不驗證密碼，也不再寫入紀錄；驗證碼錯誤不計入次數。

## 密碼

* 密碼規則：至少 8 個半形字元（只接受 0x21–0x7E，可列印 ASCII、不含空白）；大寫、小寫、數字、特殊符號四選三；不得與前 3 次相同；每 180 天須變更（次數與天數放設定檔）。
* 所有設定密碼的地方（新增、編輯、逾期變更、重設）都須呼叫**同一個方法**，由它負責規則與歷程檢查、寫入雜湊、記錄歷程並作廢重設連結，不得各自實作；種子資料例外，以靜態種子寫入預先計算的雜湊與已逾期的歷程。
* 密碼逾期時不發 JWT，改發一次性、限時的變更憑證，強制先變更密碼才能登入。

## 忘記密碼

* 嚴禁以 Email 寄送密碼（含臨時密碼），只寄一次性、限時的重設連結，由使用者自行設定新密碼；設定成功後連結立即失效。
* 重設 token 至少 256 位元；重新申請即覆蓋，舊連結隨即失效；新密碼不符規則時連結不消耗。
* 前端讀取 token 後立即從網址移除，避免留在瀏覽紀錄或 Referer。
* 連結網址一律取自設定檔，嚴禁以請求的 Host 標頭組成（防 Password Reset Poisoning）。
* 不論帳號與 Email 是否相符都回相同訊息；郵件於背景寄送，避免以訊息或回應時間探測帳號。
* 申請後不得變更或停用原密碼，避免他人藉由忘記密碼讓本人無法登入；須限制申請頻率，避免被利用大量寄信。

## 前端登入狀態

* 判斷是否已登入須同時檢查 token 存在且未超過 `expiresAt`，不可只看 `localStorage` 有無 token；過期即清除登入狀態，導覽守衛遇到過期時提示「登入已逾時，請重新登入」並導向登入頁。
* 重設密碼、逾期變更密碼成功後，先清除登入狀態再導向登入頁，由使用者以新密碼重新登入。
