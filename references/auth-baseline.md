# 登入、密碼與忘記密碼實作規範

自 `CLAUDE.md`「資安防禦規範」移出的實作細節，不會自動載入。以下時機須先讀本檔：

* `new-project` 建立登入、密碼、忘記密碼、前端登入狀態等功能時。
* `owasp-check` 檢查「身分驗證失效」類別時。
* 在既有專案修改上述功能時。

## 錯誤次數鎖定

* 帳號或密碼錯誤即記錄（帳號不存在也記錄），以最近 N 分鐘內的錯誤次數判斷是否鎖定（次數與分鐘數放設定檔）。
* 鎖定期間不驗證密碼，也不再寫入紀錄；驗證碼錯誤不計入次數。
* 錯誤紀錄的寫入與鎖定判斷一律以正規化帳號（去除前後空白後轉小寫）為準，避免以大小寫變化取得額外的嘗試次數；不依賴資料庫定序是否區分大小寫。

## 密碼

* 密碼規則：至少 8 個半形字元（只接受 0x21–0x7E，可列印 ASCII、不含空白）；大寫、小寫、數字、特殊符號四選三；不得與前 3 次相同；每 180 天須變更（次數與天數放設定檔）。
* 所有設定密碼的地方（新增、編輯、逾期變更、重設）都須呼叫**同一個方法**，由它負責規則與歷程檢查、寫入雜湊、記錄歷程並作廢重設連結，不得各自實作；種子資料例外，以靜態種子寫入預先計算的雜湊與歷程（建立日期為建立專案當日，首次登入不強制變更）。
* 密碼逾期時不發 JWT，改發一次性、限時的變更憑證，強制先變更密碼才能登入。
* 密碼變更（逾期變更、重設、管理員代設）後，先前發出的 JWT 須立即失效：JWT 帶入由密碼雜湊推導的安全戳記（不放雜湊本身），`OnTokenValidated` 查資料庫確認使用者仍啟用且戳記與目前的密碼雜湊相符（固定時間比對），不符時回 401；與啟用檢查共用同一次查詢。
* 預設管理員與預設一般使用者首次登入不強制變更密碼（種子的密碼歷程設為建立專案當日，依密碼有效天數正常到期）；種子定義見 `basic-tables.md`。

## 密碼即將到期通知

* 到期提醒天數為 `appsettings.json` 的 `Security:Password:ChecklogintimeSendMailDay`（預設 10）；0 表示不寄送，須小於 `Security:Password:ExpireDays`，超出範圍時拒絕啟動。
* 通知區間：到期日（最後一次密碼歷程時間 + `ExpireDays`）前 `ChecklogintimeSendMailDay` 天（含）起，至到期時間為止；已逾期者登入時會強制變更，不再通知。只通知啟用中的使用者，無密碼歷程者不通知。
* 區間內每位使用者每日寄送一封；當日已寄送（`BasicChecklogintimeSendMailLog` 有當日紀錄）即不再寄送，也不補寄過去未寄的日期。變更密碼後到期日重新計算，自然離開區間。
* 由背景服務（`BackgroundService`）於啟動時執行一次，之後每小時檢查一次（伺服器於固定時刻停機時，當日仍會寄出）。
  * 每小時的檢查須程序持續執行；部署於 IIS 時須設定應用程式集區不閒置關閉（`AlwaysRunning`、閒置逾時 `0`、預先載入，見 `publish-project` 部署提醒），否則只在閒置後的下一個請求啟動時檢查。
  * 測試時直接修改 `BasicPwdlog.CreatedAt` 不會立即觸發，須等下一次檢查或重新啟動應用程式（回收應用程式集區）。
* 寄送成功才寫入 `BasicChecklogintimeSendMailLog`（帳號、寄送時的 Email、寄送時間）；寄送失敗寫入 `BasicExceptionlog`（訊息以固定文字取代，不含收件人），下次檢查重試。
* 本表屬系統紀錄表，列入 `BasicSyslogSaveTracker.LogTables`，不寫入異動歷程。表中的 Email 為業務需要的寄送紀錄；`ILogger` 仍只記帳號，不記收件人與內文。
* 郵件只說明到期時間、剩餘天數與登入網址（取自 `App:FrontendUrl`），不含密碼或任何 token；範本規則同忘記密碼（放 `Template/`、啟動時載入、動態資料先 HTML 編碼）。

## 忘記密碼

* 嚴禁以 Email 寄送密碼（含臨時密碼），只寄一次性、限時的重設連結，由使用者自行設定新密碼；設定成功後連結立即失效。
* 重設 token 至少 256 位元；重新申請即覆蓋，舊連結隨即失效；新密碼不符規則時連結不消耗。
* 前端讀取 token 後立即從網址移除，避免留在瀏覽紀錄或 Referer。
* 連結網址一律取自設定檔，嚴禁以請求的 Host 標頭組成（防 Password Reset Poisoning）。
* 不論帳號與 Email 是否相符都回相同訊息；郵件於背景寄送，避免以訊息或回應時間探測帳號。
* 申請後不得變更或停用原密碼，避免他人藉由忘記密碼讓本人無法登入；須限制申請頻率，避免被利用大量寄信。
* 申請須通過驗證碼（與登入共用 `Security:Login:CaptchaEnabled` 開關，規則同登入的驗證碼）：驗證碼在比對帳號與 Email 之前檢查，錯誤時回「驗證碼錯誤」並不寄信；前端申請失敗後重新產生驗證碼。
* 郵件範本放在後端非公開目錄（如 `Template/`），**不可**放 `wwwroot`（會被直接下載）；範本於啟動時載入，檔案遺失即無法啟動，避免到寄信時才出錯（只有帳號相符才寄信，等於透露帳號是否存在）。

## 前端登入狀態

* 判斷是否已登入須同時檢查 token 存在且未超過 `expiresAt`，不可只看 `localStorage` 有無 token；過期即清除登入狀態，導覽守衛遇到過期時提示「登入已逾時，請重新登入」並導向登入頁。
* 重設密碼、逾期變更密碼成功後，先清除登入狀態再導向登入頁，由使用者以新密碼重新登入。
